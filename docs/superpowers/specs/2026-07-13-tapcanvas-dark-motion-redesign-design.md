# TapCanvas 暗色动态界面重设计规范

**日期：** 2026-07-13  
**状态：** 视觉方向已确认，本文作为实施计划与验收的设计契约  
**覆盖范围：** 未登录首页与 `/studio` 工作台外壳  
**批准方向稿：**

- 首页：`.superpowers/brainstorm/20260713-133132/content/tapcanvas-ad-concept-v4.html`
- Studio：`.superpowers/brainstorm/20260713-133132/content/studio-direction-v4.html`

方向稿中的评审选择器、状态演示开关、`/files/*` 临时资源路径及原型 SVG 图标不进入生产代码。生产实现以本文、根目录 `Design.md`、`apps/web/DESIGN.md` 和现有真实业务契约为准。

## 1. 目标与设计结论

本轮重设计解决两个表面：

1. 首页从当前抽象裂隙式单屏入口，转为「空间画布滚动 + 真实编辑器舞台」的电影化产品叙事。
2. `/studio` 从常规 SaaS 工具壳转为「静默制作台」：画布始终是主角，导航、状态、参数和 AI 对话围绕真实生产任务安静工作。

最终体验必须同时满足：

- 暗色、高级、电影化、影像优先，但不依赖噪点、颗粒、扫描线或炫光堆叠制造质感。
- 首页先建立创作空间感，再解释素材如何形成工作流，最后用真实产品舞台完成转化。
- Studio 保持高信息密度，但所有主要操作无需依赖 Tooltip 才能理解。
- 面向用户的动作、状态和导航优先使用中文；模型名、文件名、时间码、比例及业内通用元数据可保留原文。
- 视觉改造只改变呈现与布局，不改变 Canvas、store、runner、auth、API 或节点协议。

## 2. 核心体验原则

### 2.1 影像和任务优先

- 首页用真实影像、镜头关系和产品画布表达能力，不建设普通功能卡片墙。
- Studio 不新增大面积 Dashboard、指标卡、右侧 Inspector 或装饰性全局底栏。
- 工作台内的装饰必须退到内容之后；节点、媒体结果、连接关系和当前运行状态拥有最高视觉优先级。

### 2.2 高级感来自秩序而不是纹理

- 深色层级、构图比例、排版、影像裁切和克制的空间运动共同建立高级感。
- 禁止使用 `feTurbulence`、SVG/CSS 噪点、位图颗粒、film grain、scanline、抖动像素和随机闪烁纹理。
- 当前首页中的 `.tc-home-page__noise-layer` 与 `.tc-home-page__scanline-layer` 必须移除，不以改透明度的方式保留。
- 允许使用确定性的几何网格或点阵来提示「无限画布」，但必须边缘清晰、低对比、无随机扰动；建议不透明度不高于 `0.035`，且不能覆盖正文或媒体主体。
- 琥珀色只用于警告、进度节点或少量分类提示，不使用大面积橙色环境径向光。

### 2.3 单层容器与克制的玻璃感

- 遵守 `apps/web/DESIGN.md` 的「单层圆角边框」原则；不做圆角卡片套圆角卡片。
- 画布浮层可使用少量半透明背景和 blur，但拖拽、缩放及滚动热路径必须以纯色或低成本阴影为主。
- 边框用于边界、选择、焦点和错误，不作为每个内容块的默认装饰。

### 2.4 可读性高于极限密度

- 交互文字不得小于 `12px`。
- 默认正文使用 `12–13px`，优先 `13px / 18px`。
- 时间、数量、状态补充等元数据不得小于 `10px / 14px`。
- 中文正文不使用全大写效果或额外字距；等宽英文状态可使用轻微字距，但生产 UI 的状态文案仍优先中文。

## 3. 视觉系统

### 3.1 色彩角色

生产实现复用并收敛到现有暗色语义 token，不另建一套紫色或 NewAPI 风格配色。

| 角色 | 建议值 | 用途 |
| --- | --- | --- |
| 首页底色 | `#030405` | 首页沉浸背景 |
| 应用底色 | `#05070b` | Studio 最底层 |
| 画布底色 | `#07090d` | React Flow 画布 |
| 主表面 | `#0b0f14` | 面板、工具壳 |
| 抬升表面 | `#10161d` | 选中区、浮层 |
| 主文本 | `#edf3ff` | 标题与主要信息 |
| 次文本 | `#aab7ca` | 正文与按钮标签 |
| 弱文本 | `#73839a` | 辅助信息与占位 |
| 蓝色强调 | `#60a5fa` | 主要交互与焦点 |
| 青色强调 | `#22d3ee` | 当前选择、运行路径 |
| 成功 | `#34d399` | 就绪、完成 |
| 警告 | `#fbbf24` | 注意、余额、等待 |
| 错误 | `#f87171` | 失败与需要处理 |

颜色使用规则：

- 蓝青色只标记可操作、选中或运行中的内容，不铺满大面积面板。
- 成功、警告、错误色只表达真实语义，不作为装饰光源。
- 默认边框使用 `rgba(226, 232, 240, 0.08)`；焦点或选择边框使用 `rgba(125, 211, 252, 0.24)` 或等价 token。
- 首页可保留低强度蓝青环境光，但不允许其降低文字对比度或产生厚重雾化层。

### 3.2 字体层级

基础字体栈沿用 Web 设计标准：

```text
Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif
```

首页大标题可以在强调行使用一档编辑感衬线字体回退，如 `Georgia, "Times New Roman", serif`；该字体仅服务营销标题，不进入 Studio 控件与正文。

| 场景 | 规格 |
| --- | --- |
| 首页 Hero 标题 | `clamp(52px, 6.2vw, 104px)`，行高 `0.91–0.98`，字重 `600–660` |
| 首页区块标题 | `clamp(40px, 5vw, 78px)`，行高 `0.96–1.05` |
| 首页正文 | `16px / 1.65–1.72` |
| Studio 主标题 | `16px / 22px`，字重 `650` |
| Studio 节点标题、Chat 标题 | `12–13px / 18px`，字重 `650–700` |
| Studio 正文 | `12–13px / 18px`，字重 `500` |
| 按钮与常驻标签 | 最小 `12px / 16px`，字重 `600` |
| 元数据 | 最小 `10px / 14px`，字重 `600` |

### 3.3 半径、间距和阴影

- 标准小控件半径 `6px`，面板和节点 `8–10px`，首页主舞台可使用 `14–22px` 作为营销页特例。
- Studio 采用 4pt 栅格，主要间距为 `4 / 8 / 12 / 16 / 20 / 24px`。
- 同一工作台视口最多同时出现两档阴影；阴影用于浮层和聚焦，不用于每个节点内部块。
- Studio 按钮高度以 `32px` 和 `36px` 为主；图标按钮桌面最小 `32×32px`，移动端可触区域最小 `44×44px`。

## 4. 首页信息架构

首页按四幕组织，形成「感知空间 → 理解流程 → 看见产品 → 进入工作台」的连续叙事。方向稿的评审区不属于首页。

### 4.1 第一幕：Hero 与创作入口

桌面基线：

- 顶部导航位于 `top: 24px`，最大宽度约 `1220px`，高度 `58px`，使用克制的深色玻璃表面。
- Hero 最小高度约 `1040px`，内容最大宽度约 `1320px`。
- 左侧为价值主张、说明和两项动作；右侧为真实编辑器视觉舞台，外围分布 6–8 张影像卡，形成空间深度。
- 主文案延续方向稿语义：「让每个镜头，在画布中发生。」正文明确脚本、角色、场景、分镜和视频模型处于同一条连续画布链路。
- 主动作「立即进入创作画布」必须使用 `buildStudioUrl()`；不得直接拼接 `/studio` 或复制路由逻辑。
- 次动作「观看流程」滚动或聚焦到下方工作流组装段，不创建无响应按钮。

导航目标必须真实可达：

- 「创作能力」定位到工作流组装段。
- 「工作流」定位到真实产品舞台。
- 「案例」定位到产品舞台中的分镜/视频示例。
- 「文档」链接到仓库现有公开文档入口。
- 「登录」沿用现有认证入口；「进入工作台」使用 `buildStudioUrl()`。

影像卡是内容，不是噪声：默认降低少量亮度以保护文字，指针经过 Hero 时只做轻量视差和饱和度恢复，不叠加颗粒滤镜。所有装饰卡应 `aria-hidden`；承载案例意义的图片必须有准确中文 `alt`。

### 4.2 第二幕：素材组装为可运行工作流

- 使用长滚动的 sticky 舞台表达散落素材进入画布、建立节点关系并形成可运行链路。
- 桌面段落可约 `2100px` 高，sticky 舞台占满可视高度；素材位置通过滚动进度从外围收束到中心工作流。
- 动画只改变 `transform`、`opacity` 和连接进度，不在滚动中持续修改昂贵的 blur、filter 或背景纹理。
- 中央工作流在进度后半段出现，显示真实存在的脚本、分镜和视频输出关系，不展示仓库未支持的模型或功能。
- 进度两端使用中文，例如「原始素材」和「可运行画布」。

### 4.3 第三幕：真实编辑器产品舞台

- 产品舞台最大宽度约 `1180px`，桌面高度约 `690px`，以真实工作台结构为主，而不是装饰性 Dashboard。
- 提供「脚本 / 分镜 / 视频」三个可切换阶段，按钮使用中文并保留 `01 / 02 / 03` 序号作为流程提示。
- 舞台包含画布、节点/分镜/视频结果和 AI 协作区，内容只映射现有产品能力。
- 切换阶段时使用 `opacity + translateY + scale` 的短过渡；切换后焦点和 `aria-selected` 必须同步。
- 首页舞台是营销展示，不复用或改写 `Canvas.tsx`，也不与真实 store 建立第二套状态契约。

### 4.4 第四幕：收束 CTA

- 以大标题、短说明和唯一主按钮收束，不再添加卡片墙或价格表。
- 主按钮再次通过 `buildStudioUrl()` 进入工作台。
- CTA 上方可以保留低强度蓝青环境光，但不得使用噪点、扫描线或橙色大光斑。

### 4.5 首页资源和生产约束

- 原型中的 `/files/scene-*.jpg` 不是生产路径；选定媒体必须进入现有 Web 静态资源管线，使用本地导入或项目 `public` URL。
- 不从第三方站点热链图片。
- 首屏关键图预加载；首屏以下图片使用懒加载并声明稳定尺寸，避免布局跳动。
- 当前裂隙、标题破碎、噪点和扫描线结构不与新方向混搭；首页按批准的 A+D 方向整体收敛。

## 5. Studio「静默制作台」

### 5.1 信息层级

Studio 保持五层结构：

1. **画布层：** 真实 `Canvas`、节点、连线和媒体结果。
2. **顶栏层：** 宿主上下文、项目名、保存、导出和全局动作。
3. **左轨层：** 项目与领域入口。
4. **局部工具层：** 节点底部工具条、画布 Controls、Minimap、素材面板。
5. **协作层：** AI 对话的气泡、面板和聚焦三态。

画布层始终拥有最大面积。展开 AI 面板时画布可以让出右侧空间；收起或聚焦时画布恢复完整宽度。不得通过新增右侧 Inspector 再压缩画布。

### 5.2 顶栏

- 顶栏保持两行：第一行承载宿主/保存/全局动作，第二行承载 breadcrumb 与画布可见性控制。
- 保留现有 owner context、项目名、`isDirty`、`saving`、保存、导出、TapShow、主题、语言、帮助和 GitHub 行为。
- 主要动作显示「图标 + 中文文字」或纯中文文字；不能仅用一个抽象图标并要求用户悬停猜测。
- 窄屏时按优先级收起低频项，统一进入「更多」菜单；菜单项继续显示完整中文名称。保存和当前项目上下文不能被低频动作挤出。
- 必须保留 `data-tour="project-name"`、`data-tour="save-button"`、`data-tour="help-tour"`。
- 必须保留 `tc-canvas-breadcrumb-slot` 与 `tc-canvas-visibility-slot`，不改变 Canvas 向两个 slot 注入内容的机制。

### 5.3 左侧浮动导航

桌面几何契约：

- `left: 16px`
- `top: 50%`
- `width: 56px`
- `transform: translateY(-50%)`

导航入口使用现有 `@tabler/icons-react`，并在图标下常驻中文短标签：

| 入口 | 图标语义 | 常驻标签 |
| --- | --- | --- |
| 添加节点 | `IconPlus` | 添加按钮本体保持强识别，提供可见或紧邻语义 |
| 项目管理 | `IconFolders` | 项目 |
| 工作流 | `IconTopologyStar3` | 工作流 |
| 我的资产 | `IconListDetails` | 资产 |
| 漫剧工作台 | `IconLayoutGrid` | 漫剧 |
| TapShow | `IconMovie` | 展映 |
| 运行记录 | `IconTerminal2` | 运行 |
| 历史记录 | `IconHistory` | 历史 |
| 账户 | `IconUserCircle` | 账户 |

管理员看板若显示，也必须带「看板」标签。Tooltip 继续存在，作为补充解释而不是唯一名称。保留 `data-ux-floating`、`data-tour="floating-nav"` 与 `data-tour="add-button"`。

### 5.4 素材面板

- 桌面稳定位置为 `left: 82px; width: 320px`，与 `56px` 左轨保持固定间隔。
- 面板打开时不推动或重排 React Flow 节点；点击现有入口、关闭按钮或允许的画布空白区域沿用当前面板状态逻辑。
- 搜索、分类和素材名称使用可读中文；素材自身的原始文件名可保留。
- 继续保留 `data-ux-panel`，确保画布空白点击逻辑不会误关闭或穿透操作。

### 5.5 节点与节点工具条

- 不修改节点 schema、端口、连接、拖拽、选择、执行或结果写入逻辑。
- 节点正文最小 `12px`，标题 `12–13px`，元数据最小 `10px`。
- 选中状态使用青色细边框和轻量外圈，不使用持续发光或跳动。
- 节点底部工具条保持附着在选中节点下方，基线为 `top: calc(100% + 8px)` 且水平居中；不得移动为全局底栏。
- 工具条至少让「引用」「运行」显示 Tabler 图标与中文文字。模型名、比例等值可以保持原文。
- 参数编辑继续通过现有节点工具条与 `ParamModal`，不新增右侧 Inspector。

### 5.6 Controls 与 Minimap

几何契约：

- Minimap：`left: 12px; bottom: 12px; width: 160px; height: 110px`。
- Controls：`left: 12px; bottom: 130px`，横向排列。

Controls 使用「图标 + 中文文字」：放大、缩小、全览、锁定。生产实现复用 React Flow 稳定的
`.react-flow__controls-zoomin`、`.react-flow__controls-zoomout`、`.react-flow__controls-fitview` 与
`.react-flow__controls-interactive` 类，在 Studio 作用域内补充可见中文标签；同时通过 React Flow
`ariaLabelConfig` 写入对应中文可访问名称。只允许增加呈现和可访问性配置，不重写缩放、全览、锁定
handler 或交互状态。按钮文字最小 `12px`，图标 `18px` 左右。两者不得遮挡左轨、节点工具条或素材面板。

### 5.7 AI 对话三态

保留现有 `compact | expanded | maximized` 状态、偏好存储、业务消息、能力选择、引用图片、发送、中断和画布计划执行逻辑，只重构呈现。

**气泡：**

- 右下 `60×60px`。
- 显示消息图标与「AI」短标签；运行时可增加小型语义状态点，不做闪烁光环。

**面板：**

- 桌面基线 `right: 12px; top: 0; bottom: 0; width: 480px`。
- 面板头部显示「AI 对话」和当前上下文说明。
- 「新对话」「教程」「收起」「聚焦」使用 Tabler 图标与可见中文标签；窄屏允许把低频标签收起到菜单，但不得用 Tooltip 代替主要名称。
- Feed 正文 `12px`，条目标题 `13px`，时间/数量/积分元数据 `10px`。

**聚焦：**

- 居中显示，最大约 `1040×860px`，外边距至少 `16px`。
- 带 backdrop，点击 backdrop 或明确的「退出聚焦/关闭」动作恢复先前模式。
- 聚焦态不得改变消息、引用、输入草稿或当前能力状态。

面板内的附件与发送按钮位于输入框固定位置，可在空间受限时使用行业通用图标，但必须有准确的中文 `aria-label`、清晰 hover/focus 和足够点击区域；面板头部与导航类动作必须保持可见中文名称。

## 6. 中文图标语义规范

### 6.1 原则

- 生产代码统一使用现有 `@tabler/icons-react`；方向稿中的 `ti-*.svg` 仅用于原型，不复制到组件中。
- 不使用 `⌁`、`⌕`、`×`、`＋`、`▧`、`◫`、`✦` 等 Unicode 字符模拟业务图标。关闭符号应使用 `IconX`，搜索使用 `IconSearch`。
- 同一动作在顶栏、菜单、节点工具条和 Chat 中使用同一图标语义。
- 标签应描述目的而不是图形，例如用「全览」而不是「方框」，用「展映」而不是仅写品牌英文。
- icon-only 只保留在输入框内发送/附件、标准关闭按钮等强上下文位置；所有 icon-only 控件必须有中文 `aria-label` 和可见焦点。

### 6.2 文案规范

面向用户的状态与动作使用以下中文：

- `READY` → 「就绪」
- `RUNNING` → 「运行中」
- `ERROR` / `FAILED` → 「错误」或「失败」
- `AI CHAT` → 「AI 对话」
- `BUBBLE` → 「气泡」
- `PANEL` → 「面板」
- `FOCUS` → 「聚焦」
- `ONLINE` → 「在线」
- `LOCKED` → 「已锁定」
- `OUTPUT` → 「输出」

模型名、`16:9`、`4K`、`24s`、时间码和用户上传的文件名不强制翻译。

## 7. 动效规范

### 7.1 首页

- 首屏进入：标题、正文、舞台以 `opacity + translateY` 分层进入，单层时长约 `600–900ms`，总序列不超过约 `1.4s`。
- 指针视差：仅桌面精细指针启用；媒体卡位移建议不超过 `24–38px`，编辑器倾斜不超过约 `5deg`。
- 滚动组装：使用滚动进度插值卡片位置、旋转、缩放和透明度；使用 `requestAnimationFrame` 或 Framer Motion 的现有能力合并更新。
- 产品模式切换：`220–420ms`，不使用强弹簧、回弹或夸张 overshoot。
- 不新增 GSAP、Lenis、WebGL 或新的 three.js 场景。

### 7.2 Studio

- hover/focus：`120–160ms`。
- 素材面板与 AI 面板布局切换：约 `180–220ms`，使用 `cubic-bezier(0.2, 0, 0, 1)`。
- 运行路径仅在真实运行时使用短虚线位移动画；就绪时静止，错误时使用静态红色语义。
- 上传进度和节点进度来自真实状态；不得用永久循环动画伪造运行。
- 不使用持续漂浮、呼吸缩放、外发光脉冲干扰长时间创作。

### 7.3 减少动态效果

在 `prefers-reduced-motion: reduce` 下：

- 停止视差、滚动组装插值、路径流动和循环动画。
- 内容直接显示在最终位置，不因关闭动画而丢失信息。
- 保留必要的状态变化，但过渡时长降至接近即时。

## 8. 响应式行为

### 8.1 首页

| 宽度 | 行为 |
| --- | --- |
| `>= 1440px` | 完整导航、左右 Hero、全部空间媒体卡、完整产品舞台 |
| `1051–1439px` | 保留左右构图，按可用宽度缩小编辑器与媒体范围 |
| `721–1050px` | 隐藏次要导航链接；Hero 文案在上、编辑器舞台在下；减少外围媒体卡；产品头改为纵向 |
| `<= 720px` | 单列叙事；关闭指针视差与 3D 倾斜；滚动组装改为简化的顺序进入；产品舞台改为可读的单阶段展示 |

在 `390px` 视口必须满足：

- 无页面级横向滚动。
- 标题不裁切，CTA 不超出视口。
- 导航主动作可见，低频链接进入菜单或隐藏。
- 图片不会压住正文，动画关闭后仍可理解完整流程。

### 8.2 Studio

桌面基线几何在没有响应式覆盖时严格执行。窄屏覆盖如下：

| 宽度 | 行为 |
| --- | --- |
| `>= 1500px` | AI 面板 `480px`；画布预留约 `504px`；顶栏右侧避让面板 |
| `1201–1499px` | AI 面板可收窄到约 `420px`；隐藏低优先级顶栏文字，但保留关键动作语义 |
| `901–1200px` | AI 面板可收窄到约 `360px`；更多低频动作进入「更多」菜单；节点工具条隐藏非关键长字段 |
| `721–900px` | 默认把面板态降级为右下气泡，画布占满宽度；素材面板宽度不超过 `calc(100% - 110px)` |
| `<= 720px` | 单节点聚焦编辑：只显示当前选中/核心节点，其他节点和连线不挤在窄屏；顶栏提供「更多」；左轨向左收紧但保持标签可辨识 |

移动端仍保留真实 Canvas 与节点状态，不创建独立的假编辑器。Minimap 可缩到约 `132×94px`，Controls 相应上移；任何状态下都不得与左轨、节点工具条或 AI 气泡发生碰撞。

## 9. 无障碍与键盘体验

- 所有 `button`、链接、输入、tabs、segmented controls 具有准确可访问名称。
- 常驻中文标签负责第一层理解，Tooltip 只补充上下文。
- 当前导航、选中 tab、Chat 布局和展开面板使用 `aria-current`、`aria-selected`、`aria-expanded` 或等价语义。
- 键盘焦点使用可见的蓝青 focus ring，不能只靠颜色很弱的背景变化。
- 聚焦 Chat 打开时焦点进入对话区域，关闭后回到触发按钮；backdrop 不吞掉 Escape 关闭能力。
- 文本与背景对比度目标为正文至少 `4.5:1`，大字号和非文本控件至少 `3:1`。
- 状态不能只用颜色表达：就绪、运行中、错误同时提供图标/点、中文文字和必要说明。
- 图片按用途提供 `alt`；纯装饰背景、网格和光效使用 `aria-hidden="true"`。
- 移动端可触目标至少 `44×44px`；桌面紧凑控件的视觉尺寸可以较小，但点击区域不得低于 `32×32px`。

## 10. 真实状态与错误呈现

方向稿中的「就绪 / 运行中 / 错误」切换只用于审查。生产代码不加入 `data-scenario` 演示开关，不用定时器伪造状态，所有呈现必须连接现有真实状态源。

### 10.1 保存与宿主状态

- `isDirty` 显示「未保存」。
- `saving` 显示按钮 loading 和「保存中」。
- 保存成功、失败继续走现有 notifications；失败信息保留服务端可读错误文本和「保存失败」标题。
- 非项目 owner、章节宿主或本地 flow 的说明沿用现有 owner context，不改变保存目标判定。

### 10.2 工作流与节点

- 节点执行中：显示真实进度/运行标记，连接路径可流动。
- 节点成功：显示「就绪」或「完成」及真实输出摘要。
- 节点失败：节点边框、状态行和错误说明同时出现；有可重试能力时提供「重试」，没有时不创建无效按钮。
- 运行前置条件失败、启动失败和 runner 错误继续使用现有 store/notification/节点数据，不在 CSS 中硬编码业务判断。

### 10.3 上传

- 上传条只在 `hasPendingUploads()` 或现有上传状态表明有任务时出现。
- 显示真实文件数量和进度；失败项必须有中文失败原因或可追踪的原始错误消息。
- 不用无限循环进度条代替未知状态；未知进度使用明确的「处理中」而不是虚假百分比。

### 10.4 AI 对话

- `sending` 显示「生成中」和现有中断动作。
- 网络、服务、能力加载、项目文本素材加载、canvas plan 执行和后端写画布失败均沿用现有错误来源。
- 错误消息应出现在与任务相关的 Chat 区域或现有 notification 中，包含「发生了什么」与现有可执行恢复动作。
- 失败不会清空草稿、引用图片、已收到消息或当前能力选择。
- 只修改错误的视觉层级和中文可读性，不修改 `AiChatDialog` 的请求、解析、tool gating、trace 或画布执行契约。
